## Problem statement
When a TOML document ends with a backslash inside a basic string, the escape parser advances two characters even though only one remains. The resulting public error position can be one character beyond the document. This is the error-position problem described in tomli issue 312; the local code supports that diagnosis, but no runtime reproduction has been performed in this investigation.

## Proposed outcome
Correct the trailing-backslash error position while keeping everything else about error positions as it is. Cover basic string values, multiline basic string values, and double-quoted keys through their shared escape-parsing path. The proposed regression checks public numeric positions as well as displayed locations.

## Acceptance criteria

For a TOML document ending with a backslash inside a basic string value, multiline basic string value, or double-quoted key, report pos at the end of the document, never beyond it, while keeping everything else about error positions as it is.
not yet runnable: tests/test\_trailing\_backslash\_position.py does not exist yet. Add a unittest test\_trailing\_backslash\_reports\_eof covering basic values, multiline values, and double-quoted keys, plus unchanged-position controls. The explicit module invocation must fail if the module is absent. Establish candidate-source import provenance before interpreting results. The intended pre-fix or targeted-reversion red is the pos == len(document) assertion receiving len(document)+1; this has not been executed.

The existing error-location and public TOMLDecodeError attribute tests continue to pass.
check: `PYTHONPATH=src python3 -m unittest tests.test_error`

## Affected users and systems
Users of tomli who inspect TOMLDecodeError positions or display its diagnostics are affected. The proposed implementation surface is src/tomli/_parser.py, with focused coverage in a new tests/test_trailing_backslash_position.py and compatibility coverage from tests/test_error.py. Shared string and quoted-key callers make a parser-wide position adjustment risky.
